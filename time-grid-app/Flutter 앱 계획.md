# 시간 그리드 Flutter 앱 계획 (포트폴리오)

2026-10-29 작성. 제작은 PC에서 한다. 실험 내용은 `시간 그리드 사고 실험.md`가 기준이다.

## 목표

- 시간 그리드 사고 실험을 Flutter 앱으로 옮겨, 그리드 규칙이 실제로 동작하는 모습을 보여 준다.
- AI를 이용해 Python 실험 코드를 Dart로 변환하고, 결과물을 포트폴리오로 쓴다.

## 원칙

1. **앱 안에서 실제로 계산한다.** 가벼운 실험은 Dart로 직접 계산해 실시간으로 보여 주고, 무거운 3D 실험만 저장된 데이터를 재생한다.
2. **물리 계산과 화면을 나눈다.** 물리 계산은 순수 Dart 패키지(`physics/`)로 두고, 화면은 그것을 불러 쓴다. 계산은 Isolate로 UI와 분리하고, 2D 격자 파동은 가능하면 셰이더(GPU)로 돌린다.
3. **변환이 맞다는 것을 테스트로 증명한다.** Python 결과를 기준값으로 단위 테스트를 만든다. AI 변환은 부호, FFT 정규화, 격자 미분이 조용히 틀어지기 쉽다.
4. **측정 원칙에 맞는 값만 그린다.** 시계 속도, 틱으로 잰 거리, 궤적처럼 관측 가능한 값만 보여 준다. 막 변형 h를 그대로 그리면 이름표 성분 때문에 아무 일 없는 곳도 출렁여 보인다.
5. **AI 사용을 밝힌다.** README에 "물리 모형과 실험 설계는 직접, Python→Dart 변환과 일부 구현은 AI 도움, 정확성은 기준값 테스트로 확인"을 적는다.
6. **링크 하나로 열리게 한다.** Flutter Web으로 빌드해 GitHub Pages(anchiuk.github.io/Homepage)에 함께 올린다. Android 빌드는 덤.

## 주의

- 3D 160³ 계산은 PC에서도 20분 넘게 걸리므로 앱에서 실시간으로 돌리지 않는다.
- 실험을 새로 돌리는 일은 계속 Python(`time-grid/`)에서 하고, 앱은 보여 주는 역할만 한다.
- 실시간 화면은 격자를 줄이므로 기준값과 조금 다를 수 있다. 테스트는 Python과 같은 크기로, 화면은 줄인 크기로 돌린다.

## 진행 기록

- 2026-11-02: PC에 Flutter 3.47.9(stable) 설치. 앱 뼈대(웹 + Android), 화면 1 "막의 떨림" 완료. Dart 변환은 Python 기준값과 상대 10⁻⁹ 안에서 같음(테스트 10개). 웹 빌드는 `time-grid-app/app/`에 올림. 1D는 가벼워서 Isolate 없이 화면 쪽에서 계산함(2D부터 Isolate 또는 셰이더).
- 2026-11-02: 화면 2 "빛의 휘어짐" 완료. 원본과 같은 영역을 256²(간격 0.12)로 계산, 속도 3가지(v = 0.44 / 0.68 / 0.77), γ = 1 / 0 전환, 휨을 1 + γv² 예측선과 원본 Python 점 위에 찍음. 브라우저에서 한 번 진행 약 6초. 기준값 테스트는 원본 크기 768²와 화면 크기 256² 모두 Python과 상대 10⁻⁸ 안.
  - 결정: 셰이더 대신 CPU(Dart) 계산. 웹에는 Isolate가 없으므로 한 프레임에 약 12 ms씩 나눠 계산. 384²는 브라우저에서 한 번에 20~30초라 256²로 줄임(같은 속도에서 원본과 1.5% 안, 대신 q = 8 이상은 격자가 거칠어 뺌). wasm 빌드는 이 계산에서 JS보다 빠르지 않았음.
  - 주의: 세 점으로 맞춘 γ는 원본 크기에서도 약 1.2로 나옴(원본의 1.04는 v = 0.92 점까지 넣은 값). 그래서 화면은 맞춘 γ 대신 점과 예측선을 보여 줌.
- 2026-11-02: 화면 3 "두 덩어리 궤도" 완료. 원본과 같은 영역을 128²(간격 0.5), dt 1.0으로 계산. 시작할 때 바닥 상태(스스로 묶인 모양)를 허수 시간으로 찾고(브라우저 몇 초, 한 번만), 두 덩어리를 원 궤도 속도로 보냄. 서로 끌림 켬/끔 전환, 시계 지도 위 궤적, 돈 각도와 케플러 예측 비교.
  - FFT는 직접 구현(2의 거듭제곱, numpy와 같은 정규화). 두 덩어리의 시계 몫은 복소 FFT 한 번으로 함께 계산(실수 핵이므로).
  - 128²의 궤도: 1.25주기 동안 493°, 최소 거리 10.52 (원본 256²: 486°, 10.90). dt 1.0 / 0.5 / 0.25가 같은 궤도.
  - 기준값 테스트: 원본 크기 256²(바닥 상태 + 처음 100 시간 단위)와 화면 크기 128²(1.25주기) 모두 Python과 중심 위치 10⁻⁷ 안.
- 2026-11-02: 화면 4 "중력파" 완료. 첫 범위(화면 4개) 끝.
  - 모드 세기: 후보 C3(규칙) / C1(대조), 진행 방향 4가지, 파수 × 격자 간격 0.05~1.5를 바꾸면 앱이 6×6 일반화 고윳값 문제를 바로 풀어 출렁임 / 이름표 / 구속 개수와 속도를 보여 줌. 규칙은 언제나 출렁임 2, 이름표 3, 구속 1.
  - 중력파 재생: 3D 96³ 계산의 저장 장면(`time-grid/viz_data/gw_free_{plus,cross}.json`을 앱 assets로 복사). xz 단면의 펄스와 z = 0 고리 표지 16개의 틱으로 잰 거리(300배 과장). 처음 모양(이름표 성분, 출렁이지 않음)과 지금 모양을 겹쳐 그림.
- 다음 후보: 계획의 "그다음"(3D 실험 2-b-1·2-b-2·2-b-3·비선형 2의 viz_data 재생), Android 빌드, 휴대폰 화면 확인.
